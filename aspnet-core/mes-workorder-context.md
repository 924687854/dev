## 4. 已确认需求

### 4.1 总体目标

在当前后端项目基础上，从零开始设计并逐步实现 MES 的工单模块，参考金蝶云星空的工单设计思路，但不要求 1:1 复制。

### 4.2 当前明确范围

- 只聚焦工单功能
- 基于现有仓库直接新增模块
- 暂不做前端
- 需要同时支持：
  - 生产工单
  - 工序工单
- 工单来源需要支持：
  - 手工创建
  - 外部系统通过接口调用生成
- 首版目标优先做到：
  - 数据模型
  - 状态流转
  - 创建接口
- 首版创建接口范围：
  - 仅开放生产工单创建
  - 工序工单不能独立创建
  - 工序工单只能由生产工单生成
  - ERP 传入 MES 的生产工单默认处于已下达状态
  - 手动下达一般只出现在测试场景
- 首版工艺路线规则：
  - 创建生产工单时，系统先自动匹配工艺路线
  - 匹配规则按产品编码 + 生产组织 + 生效版本/日期进行匹配
  - 如果存在匹配的工艺路线，则自动关联
  - 如果没有匹配到工艺路线，仍允许创建生产工单
  - 一张生产工单只允许绑定一个工艺路线版本
  - 新版本工艺路线可设置生效时间，到达生效时间后，新创建的生产工单默认匹配并采用新生效版本
  - 下达状态下允许修改默认匹配的工艺路线，但必须记录变更日志
  - 生成工序工单前必须补齐并确认工艺路线
  - 一旦生成工序工单，工艺路线版本锁定，不允许直接修改
  - 如需修改工艺路线，必须先物理删除工序工单，再修改工艺路线后重新生成工序工单
  - 仅未开工的工序工单允许物理删除

## 5. 当前业务理解与假设

以下内容是当前阶段的工作假设，若用户后续确认不同，应以最新确认为准：

1. “工单”优先指生产制造场景中的生产工单与工序工单。
2. 生产工单是主单据，用于承载产品、数量、计划时间、来源、状态等主业务信息。
3. 工序工单是执行单据，用于承载某道工序的派工、开工、完工、报工等执行信息。
4. 工序工单与生产工单之间默认存在主从或分解关系。
5. 外部系统接口生成，当前确认优先通过 API 创建生产工单。
6. 在当前业务语义下，ERP 传入 MES 的生产工单默认应视为已下达；手动下达通常只用于测试场景。
7. 当前尚未确认是否涉及审批、委外、返工、拆单、合单、齐套、批次、序列号等扩展能力。
8. 工序工单理论上只能由生产工单生成，不允许被手工或外部接口独立创建。
9. 工序工单在首版中由用户手动触发“生成工序工单”后生成，而不是在创建或下达生产工单时自动生成。
10. 工序工单生成必须依赖工艺路线；没有工艺路线时，首版不允许生成工序工单。
11. 创建生产工单时，系统应先尝试自动匹配工艺路线；匹配成功则自动关联，匹配失败也允许建单。
12. 工艺路线自动匹配规则在首版中按产品编码 + 生产组织 + 生效版本/日期进行判定。
13. 一张生产工单在首版中只允许绑定一个工艺路线版本。
14. 工艺路线新版本可配置生效时间，到达生效时间后，新创建的生产工单默认匹配新生效版本；已创建工单不自动切换。
15. 在未生成工序工单之前，即使生产工单已处于下达状态，也允许修改系统默认匹配的工艺路线，但必须记录变更日志。
16. 工艺路线变更日志在首版中至少记录修改人、修改时间、修改前后路线版本、修改来源（手工/接口）。
17. 修改原因字段不纳入首版，作为后续迭代内容。
18. 用户要求接口来源日志按标准审计追踪要求设计；由于不存在唯一统一的 MES 审计字段标准，按通用企业审计追踪基线处理。
19. 首版接口来源日志基线确认记录到接口系统标识与 RequestId。
20. 工艺路线既然存在生效日期，就应同时存在失效日期或等价的有效区间约束；同一产品编码 + 生产组织下，不应出现有效期重叠的多个版本同时命中。
21. 如果出现多条工艺路线同时满足匹配条件，属于主数据错误，而不是正常业务场景。
22. 此类有效期重叠错误应在创建或维护工艺路线主数据时直接报错并阻止保存，而不是等到创建生产工单时再处理。
23. 因此前提下，生产工单创建阶段默认不再承担“多版本同时命中”的兜底选择逻辑。
24. 对于未匹配到工艺路线的生产工单，生成工序工单前必须人工补齐并确认工艺路线。
25. 一旦生成工序工单，工艺路线版本在首版中锁定，不允许直接修改。
26. 如需修改工艺路线，业务规则为先物理删除既有工序工单，再修改生产工单上的工艺路线，最后重新生成工序工单。
27. 物理删除工序工单的前置条件为“未开工”；一旦工序已开工，首版不允许删除并重生。
28. 从产品和实施风险角度，这一策略兼顾了建单灵活性与执行标准化，适合首版落地。
29. 虽然首版范围包含数据模型、状态流转和创建接口，但实际实施顺序建议采用分阶段方式：先定领域模型，再定状态机，最后落接口。
